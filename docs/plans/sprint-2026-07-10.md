live updates that survive a reconnect, and entry docs / committed state that tell
the truth about the just-shipped UI 2.0 rebuild. Reconcile the contracts the
rebuild's velocity outran (PHILOSOPHY §2 "files where they help", §8 "stable,

then revised per maintainer review: create-form correctness elevated to must-ship,
spacing reframed as a rules pass that gates other CSS work, components.js split

## Standing rules

- No CSS-touching card starts before the spacing-rules pass (`card_72ebfbee`) lands.
- UI-changing cards attach a wireframe/mockup to the card for review **before** implementation.
- Small PRs to `main` after the P1b merge; `frontend-rebuild → main` only, other branches rebase later.
- Phase exits update card statuses (dual-backlog mitigation); sprint close exports + commits the JSONL once.

## Risks

- **P3b seam may not exist** → drop after ~2 days; a duplicate temporal evaluator is worse than a missing feature.
- **Node interop spike fails** → fall back to plain `module.exports` extraction; never blocks live hardening.
- **Board-create is server work** and may balloon → server side alone is the must-ship; client polish trails.
- **JSONL overwrite could destroy groomed state** → backup + scratch export + 3-way diff encoded in P1b.
- **Branch drift** → merge at P1b exit; everything after targets `main`.
- **Dual backlog (this doc vs board)** → the board wins; phase exits sync statuses; sprint close commits the snapshot.
